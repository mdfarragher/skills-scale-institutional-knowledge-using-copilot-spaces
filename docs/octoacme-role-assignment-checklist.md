# OctoAcme — Role Assignment Checklist

Use this checklist when starting a new project to ensure all key roles are assigned and accountabilities are clear. For full role definitions and the interaction model, see [Roles & Personas](./octoacme-roles-and-personas.md).

---

## Role Assignment

- [ ] **Project Manager** assigned — name: _______________
- [ ] **Product Manager** assigned — name: _______________
- [ ] **Technical Lead** assigned — name: _______________
- [ ] **QA Lead / Quality Owner** assigned — name: _______________
- [ ] **UX Designer** assigned (or noted as shared/deferred) — name: _______________
- [ ] **Support / Customer Advocate** assigned (or noted as shared/deferred) — name: _______________
- [ ] **Release Manager** assigned (or confirmed as PM responsibility) — name: _______________

---

## Accountability Confirmation

- [ ] Technical Lead has reviewed project scope and flagged major technical risks
- [ ] QA Lead has confirmed test strategy and defined quality gates for this project
- [ ] UX Designer has reviewed feature scope and identified any user research needs
- [ ] Support / Customer Advocate has been briefed on the project and feedback channels established
- [ ] Release Manager (or PM) has reviewed the release plan and deployment checklist
- [ ] RACI-lite interaction model reviewed with team (see [Roles & Personas](./octoacme-roles-and-personas.md))

---

## Communication Setup

- [ ] All role holders added to the relevant communication channels (Slack, Teams, etc.)
- [ ] Weekly sync cadence agreed between PM, PdM, Technical Lead, and QA Lead
- [ ] Stakeholder update schedule set (see [Project Management Overview](./octoacme-project-management-overview.md))
- [ ] Project board set up with QA column; QA Lead owns the QA column (see [Execution & Tracking](./octoacme-execution-and-tracking.md))
